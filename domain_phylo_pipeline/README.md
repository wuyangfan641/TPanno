# Domain-based phylogeny and protein-family clustering (HMMER + MAFFT + trimAl + IQ-TREE)

A reproducible pipeline for **Ubuntu/Linux servers**. It takes one protein FASTA per sample (the TickPathDB analysis uses 27 proteomes), identifies domains with Pfam profile HMMs, and extracts **only the HMM-defined homologous domain region** for multiple sequence alignment, trimming, and maximum-likelihood tree inference. It then performs patristic-distance clustering on each tree and reports subfamily assignments, sample composition, branch support, and QC metrics.

> **Design principle: never align whole proteins directly.** Across species, N- and C-terminal regions, low-complexity regions, signal peptides, and non-homologous segments can severely distort alignments and tree topology. The HMM first defines the homologous domain boundaries, and only that region is aligned. This is the core of "domain-based phylogeny".

---

## 1. Confirm the structure of your input data

The pipeline assumes that **the 27 files are 27 protein sets that have not yet been partitioned into families** (one file per sample/species), not 27 pre-defined gene families. Each file is therefore treated as one sample. Pfam HMMs are used to discover domain families, and clustering is then performed within each domain family ("domain family to subfamily"). This is exactly what the full-Pfam `hmmscan` mode below is designed for.

If your files are in fact **27 pre-defined gene families** (one family per file), do not interpret the results as 27 samples/species. Instead, choose one HMM per family and run `search -> domains -> phylo -> cluster` separately for each family, or adapt `samples.tsv` and the input layer of `00_prepare_inputs.py`. The biological interpretation differs between the two designs, so confirm the structure before running the pipeline.

```text
00_raw/
├── Athaliana.pep.fasta      # sample A
├── Osativa.pep.fasta        # sample O
├── ...                      # 27 files in total
```

The second required input is a set of **domain HMMs**:

- **Recommended:** extract the HMMs of the families you care about from Pfam-A (tens to hundreds of models) and place them in `01_hmms/`.
- **Alternative:** run an **HMM-guided full-library scan** of Pfam-A with `SEARCH_MODE=hmmscan`, then use `MIN_SAMPLES`, copy-number, and clan metrics to retain conserved and interpretable domain families. This is computationally expensive and can yield thousands of candidate families; it is not unsupervised clustering from sequence alone.

## 4. Preparing the inputs

### 4.1 Add the protein FASTA files

```bash
mkdir -p 00_raw
# Suggested filename: <species>.pep.fasta; the sample name is inferred from it
```

Requirements:

- Protein sequences (amino acids), not CDS.
- Sequence IDs must be **unique within each file**. Duplicate IDs cause the QC step to abort.
- `*` is allowed: terminal stops are removed and internal stops are converted to `X` by default. `X/B/Z/J` and `U/O` are accepted; `U/O` are converted to `X` by default.
- Avoid spaces, parentheses, colons, commas, and semicolons in IDs, because they can break Newick parsing. The pipeline sanitizes IDs downstream but keeps the original IDs in `metadata.tsv`.

### 4.2 Prepare the HMMs

**Option A (recommended): extract only the target families**

```bash
# pfam_ids.txt contains one Pfam name per line; comments are allowed
cat > pfam_ids.txt <<'EOF'
PF00069.28   # Pkinase
PF07714.17   # PK_Tyr_Ser-Thr
PF00001.23   # 7tm_1
EOF

bash bin/00_prepare_hmms.sh \
    --pfam /path/to/Pfam-A.hmm \
    --names pfam_ids.txt \
    --out 01_hmms/selected.hmm
```

**Option B: full Pfam scan (HMM-guided, staged; `run_pfam_scan.sh` is recommended)**

```bash
# 1) Prepare Pfam-A and run hmmpress once
cp /path/to/Pfam-A.hmm 01_hmms/
hmmpress -f 01_hmms/Pfam-A.hmm

# Optional: clan map for 03b --collapse-clans, which avoids
# inferring trees for redundant models in the same clan
wget -O 01_hmms/Pfam-A.clans.tsv.gz \
  https://ftp.ebi.ac.uk/pub/databases/Pfam/current_release/Pfam-A.clans.tsv.gz
gunzip -f 01_hmms/Pfam-A.clans.tsv.gz

# 2) Full Pfam scan + family screening + tree inference for selected families
MIN_SAMPLES=22 MIN_SEQS=22 MAX_FAMILIES=300 \
HMMSEARCH_CPU=8 JOBS=2 THREADS_PER_JOB=8 \
bash run_pfam_scan.sh
```

This does not scan everything and then build thousands of trees. Instead:

```text
hmmscan the full library (27 domtblout files)
  -> 03 writes all candidate families using lenient thresholds (MIN_SAMPLES=1, MIN_SEQS=4)
  -> 03b applies the real 22/22 thresholds plus copy-number, coverage, and clan filters
  -> MAFFT/trimAl/IQ-TREE run only for selected families
  -> 06 summarizes the results
```

**Why screening is necessary**

- A full Pfam scan produces thousands of domain families. Many are paralogous, fragmented, low-coverage, or redundant models from the same clan. Inferring trees for all of them is neither computationally feasible nor biologically interpretable.
- `MIN_SAMPLES` only answers "in how many samples does this family occur"; it does not answer "is this family suitable for phylogenetics". Also examine `median_hmm_cov`, `median_domain_len`, `single_copy_fraction`, `median_copies`, and whether the models belong to the same clan.
- With 27 species, `MIN_SAMPLES=14` means "most species" (>50%), whereas `MIN_SAMPLES=22` means "conserved family" (>=80%). These thresholds have different biological meanings; do not conflate them.
- `MAX_FAMILIES=300` is a feasible size for a first pass. Increase it after validating the workflow, or group families by clan or function. The screening score favours families with high sample coverage and a high single-copy fraction, so the selected 300 are not a random sample and cannot be used to estimate the proportion or distribution of all Pfam families.

If the goal is not "domain-family clustering" but "one orthologous copy per species", add:

```bash
MAX_MEDIAN_COPIES=1 MIN_SINGLE_COPY_FRAC=0.8 bash run_pfam_scan.sh
```

This excludes families in which most samples have multiple paralogous copies. The cost is that many genuine gene-duplication families are discarded, so decide based on your biological question.

Files written by `run_pfam_scan.sh`:

```text
results/03_domains/screen/
├── family_screen.tsv      # metrics for all families and selection status
├── selected_families.tsv  # selected families
├── family_list.txt        # selected family names
├── family_dirs.txt        # selected family directories (allowlist for 04/05)
└── screen_report.md
```

> Important: `SEARCH_MODE=hmmscan` requires an `hmmpress`ed database. `hmmscan` loads the entire pressed database into memory, so `JOBS` parallel processes use `JOBS` copies of that memory. The `domtblout` files and SQLite database for 27 samples can reach tens of GB. Check disk and memory with `df -h` and `free -h` before starting.

### 4.2.1 Recommended settings for a 104-core / 800 GB server

The machine has enough resources for a full Pfam scan, but do not let 104 processes compete for memory and I/O. Recommended:

```bash
# Full Pfam scan + screening + trees for 300 selected families
JOBS=24 \
HMMSEARCH_CPU=4 \
THREADS_PER_JOB=4 \
MIN_SAMPLES=22 \
MIN_SEQS=22 \
MAX_FAMILIES=300 \
bash run_pfam_scan.sh
```

Resource budget:

| Stage | Concurrency | Threads per task | Total threads | Notes |
|---|---:|---:|---:|---|
| `hmmscan` | 24 | 4 | 96 | 27 samples in 2 batches (24 + 3); leave 8 cores for the system |
| MAFFT/trimAl | 24 | 1 | 24 | MAFFT itself is single-threaded, so CPU use is low at this stage |
| IQ-TREE | 24 | 4 | 96 | 300 families in about 13 batches |
| 05 clustering | 24 | 1 | 24 | Distance matrices are O(n^2); this is usually not the bottleneck |

If families are generally large (>500 sequences), use the more conservative `JOBS=13 THREADS_PER_JOB=8` (104 threads, lower memory pressure). If families are small and throughput matters, `JOBS=48 THREADS_PER_JOB=2` is possible, but watch per-task memory when 48 IQ-TREE jobs run at once.

Memory per `hmmscan` process depends on the Pfam release and `--cpu`, so do not copy these values blindly. First scan 2-3 samples, observe the peak with `free -h`, and then choose `JOBS`. With 800 GB of RAM, `JOBS=24` is safe, but reserve at least several hundred GB of disk for `domtblout` and `hits.sqlite`.

### 4.3 Generate the sample table and run QC

```bash
bash run_pipeline.sh --init
```

This writes `config/samples.tsv` (27 rows) and `results/00_prep/input_qc.md`. Check that the sample names are readable and the sequence counts are plausible. If necessary, edit the `sample` column of `samples.tsv` and rerun:

```bash

```

## 5. Running the pipeline

```bash
# 8 families in parallel; 4 threads per IQ-TREE job
bash run_pipeline.sh --jobs 8 --threads 4
```

Resume after interruption: completed steps and families are skipped by default; `--force` overwrites existing results.

Run only a subset of steps:

```bash
bash run_pipeline.sh --from phylo --to cluster
```

Preview the commands without executing them:

```bash
bash run_pipeline.sh --dry-run
```

**CPU planning:** the number of concurrent IQ-TREE jobs (`JOBS`) times the threads per job (`THREADS_PER_JOB`) should not exceed the number of available cores. For example, 32 cores can use `--jobs 8 --threads 4`, and 16 cores can use `--jobs 4 --threads 4`. In the HMMER stage, `config.sh` defaults to one CPU per task; `run_pfam_scan.sh` uses eight CPUs per `hmmscan` task unless `HMMSEARCH_CPU` is set.

## 6. What each step does and why

### Step 00: input QC and normalization

- Remove whitespace, `-`, and `.`; remove terminal `*`; convert internal `*` to `X` by default.
- Convert `U/O` to `X` by default (HMMER's 20-letter models do not model these rare amino acids).
- Discard sequences shorter than `MIN_PROTEIN_LEN` (default 30 aa) or with an `X` fraction above `MAX_X_FRAC` (default 50%).
- **Abort on duplicate IDs.** Downstream code uses `sample|protein` as the unique key, and duplicate IDs would misassign domains.
- Write `results/00_prep/clean_fasta/*.faa`; the raw files are never modified.

### Step 02: HMMER search

- `hmmsearch` mode: search each `HMM_DIR/*.hmm` against each of the 27 samples.
- `hmmscan` mode: scan each sample once against an `hmmpress`ed database.
- Prefer the **Pfam gathering threshold (`--cut_ga`)**, a manually calibrated threshold that balances sensitivity and specificity and is more defensible than an arbitrary `1e-5`. If an HMM file lacks GA lines, the pipeline falls back to `-E $HMM_EVALUE_MAX` automatically.
- Write `--domtblout`, which records the independent i-Evalue and the HMM/sequence coordinates of each domain.

**Tool note.** HMMER provides the profile HMM search engine (Eddy, 2011), and the domain models and gathering thresholds come from Pfam (Mistry et al., 2021).

### Step 03: domain filtering and extraction

Each domain hit is filtered in the following order:

| Filter | Default | Rationale |
|---|---|---|
| i-Evalue | <= 1e-3 (fallback in GA mode; 1e-5 is recommended in `evalue` mode) | Conservative lower bound on top of the GA threshold; can be relaxed in the config |
| HMM coverage `(hmm_to-hmm_from+1)/qlen` | >= 0.70 | Removes fragmented hits that cover only a small part of the model |
| Domain length | >= 30 aa | Fragments that are too short carry little phylogenetic signal |
| `X` fraction within the domain | <= 0.30 | Prevents unknown characters from dominating the alignment |
| Copies per protein per family | Keep only the copy with the highest HMM coverage | Avoids fragmented hits; ties are broken by i-Evalue and score; `KEEP_ALL_DOMAINS=1` keeps all copies |

**Coordinate choice:** by default, the HMMER `ali` coordinates (the region that was actually aligned) are used, not the whole protein and not the `env` envelope. `ali` is cleaner. If conserved extensions beyond the domain boundary matter, set `DOMAIN_COORD="env"` and increase `DOMAIN_FLANK`.

Output:

```text
results/03_domains/<family>/
├── <family>.domains.faa     # domain subsequences only
└── metadata.tsv             # coordinates, E-values, sample, protein ID, domain length, ...
```

**Order of preference for the best copy:** HMM coverage first (is the domain complete?), then i-Evalue, then score. Ranking by i-Evalue alone favours "local but highly significant" fragments and biases the downstream alignment.

In full-Pfam mode, `03b_screen_families.py` runs after this step and filters by sample coverage, copy number, coverage, and clan redundancy. Only selected families proceed to 04/05.

### Step 03b: full-Pfam family screening (hmmscan mode only)

`03b_screen_families.py` reads `03_domains/families.tsv` and each family's `metadata.tsv`, and computes:

| Metric | Meaning | Default filter |
|---|---|---|
| `n_samples` | Number of samples in which the family occurs | `MIN_SAMPLES` (27 species: 14 = majority, 22 = conserved) |
| `n_seqs` | Number of domain sequences | `MIN_SEQS` |
| `median_hmm_cov` | Median HMM coverage | `MIN_MEDIAN_COV=0.75` |
| `median_domain_len` | Median domain length | `MIN_MEDIAN_DOMAIN_LEN=30` |
| `single_copy_fraction` | Fraction of samples with exactly one copy | `MIN_SINGLE_COPY_FRAC` (0 = no limit) |
| `median_copies` | Median copies per sample | `MAX_MEDIAN_COPIES` (0 = no limit) |
| `clan` | Pfam clan | With `--collapse-clans`, only the highest-scoring model per clan is kept |

Outputs are `family_screen.tsv`, `family_list.txt`, `family_dirs.txt`, and `screen_report.md`. `MAX_FAMILIES` controls the size of the first tree-inference round; `0` means no limit.

> Note: a low `single_copy_fraction` does not make a family invalid. It means the family is strongly affected by gene duplication or paralogy. Such families can still be used for "domain-family clustering", but they cannot be treated directly as orthogroups and must not be used to infer a species tree.

### Step 04: MAFFT -> trimAl -> IQ-TREE

**Alignment**

- `n <= 200`: `mafft --localpair --maxiterate 1000` (L-INS-i, the most accurate option for up to about 200 sequences).
- `n > 200`: `mafft --auto` (selects an algorithm automatically and avoids the O(n^2) memory and time cost of L-INS-i).
- Optional `ALIGNER="hmmalign"`: align within the HMM coordinate frame with `hmmalign --trim`; useful for highly divergent families. Requires `HMM_SOURCE` to be able to fetch the corresponding model from Pfam-A.

**Trimming**

- Default `trimal -gappyout`: chooses the gap threshold from the overall gap distribution; data-driven and reproducible.
- Alternative `-automated1`: trimAl's heuristic designed for maximum-likelihood tree inference; usually more aggressive.
- Families with fewer than `TRIMAL_MIN_COL` columns (default 30) after trimming are discarded.
- If the retained fraction is below 30% of the original alignment, a warning is written but the family is not stopped automatically.

**Tree inference**

```bash
iqtree2 -s <trim.fa> -st AA -m MFP -B 1000 -bnni -alrt 1000 \
        -T <threads> -seed 12345 --prefix iqtree
```

- `-m MFP`: ModelFinder Plus, selecting among candidate protein substitution models by **BIC**.
- `-B 1000 -bnni`: 1000 ultrafast bootstrap replicates, with nearest-neighbor interchange correction for UFBoot overconfidence (Hoang et al., 2018).
- `-alrt 1000`: SH-aLRT as a second support measure.
- **No automatic rooting.** Trees are unrooted by default. Clustering uses patristic distances on the unrooted tree. IQ-TREE roots with `-o` only when `OUTGROUP` is provided. Without a reliable outgroup, forced midpoint rooting would create spurious "basal" interpretations, so the pipeline does not do it by default.

**Tool note.** MAFFT performs the multiple sequence alignment (Katoh & Standley, 2013), trimAl performs alignment trimming (Capella-Gutiérrez et al., 2009), and IQ-TREE 2 performs maximum-likelihood inference (Minh et al., 2020) with ModelFinder model selection (Kalyaanamoorthy et al., 2017) and UFBoot2 support (Hoang et al., 2018).

### Step 05: tree-based clustering

1. Compute pairwise **patristic distances** between all tips (expected substitutions per site).
2. Perform hierarchical clustering on the distance matrix. The default is **complete linkage**, which guarantees that the maximum pairwise patristic distance within a cluster is <= t and is less prone to chaining than average linkage; `average` is also available. This definition is close to the cluster-diameter objective of TreeCluster (Balaban et al., 2019).
3. Cut the dendrogram at `CLUSTER_CUTOFF` (default 0.50 substitutions per site).
4. Report for each cluster:
   - number of sequences, number of samples, and sample composition;
   - mean and maximum within-cluster distance, and minimum between-cluster distance;
   - silhouette;
   - whether the cluster is monophyletic, and the **UFBoot / SH-aLRT** support of the corresponding branch.
5. Also write `cutoff_scan.tsv`: the number of clusters, singleton fraction, and mean silhouette at different thresholds. Use it to check whether the chosen threshold lies on a plateau rather than picking it arbitrarily.

> In `cluster_summary.tsv`, `n_seqs` is the number of tree tips and `n_members` is the number of sequences after mapping CD-HIT representatives back to all members. Without dereplication, the two values are identical.

> Why not use a simple sequence-identity threshold? The tree already models multiple substitutions, site-rate heterogeneity, and the amino-acid replacement matrix. Patristic distance is closer to true divergence than raw identity and is consistent with the tree visualization. However, **no single threshold is an objective species or subfamily boundary**; the final interpretation should combine domain architecture, synteny, expression, and functional evidence.

**Tool note.** CD-HIT performs greedy sequence dereplication for very large families (Fu et al., 2012). The tree and distance calculations use Biopython (Cock et al., 2009), NumPy (Harris et al., 2020), and SciPy (Virtanen et al., 2020); Python 3.11 is used throughout (Python Software Foundation, 2026).

### Step 06: summary report

`results/06_report/report.md` summarizes:

- the number of domain sequences, number of sequences used for tree inference, alignment columns, trimmed columns, best model, and number of clusters for each family;
- the 15 largest clusters and their support values;
- automatic QC alerts (over-trimming, too few sequences, tree inference failure, and so on);
- a parameter snapshot (`parameters.tsv`) and software versions (`software_versions.txt`) for the methods section.

## 7. How to read the result files

| File | Purpose |
|---|---|
| `results/00_prep/input_qc.md` | Start here: sequence counts, lengths, and unusual characters for the 27 samples |
| `results/03_domains/families.tsv` | Which families passed the thresholds, and how many sequences/samples each has |
| `results/03_domains/screen/family_screen.tsv` | Full-Pfam mode: sample coverage, copy number, coverage, clan, and selection status |
| `results/03_domains/screen/family_list.txt` | Selected family names (can be passed to 04/05) |
| `results/03_domains/screen/screen_report.md` | Screening thresholds and top families |
| `results/03_domains/<family>/metadata.tsv` | Sample/protein of origin, coordinates, and E-value for each domain |
| `results/04_phylo/<family>/iqtree.treefile` | ML tree with `SH-aLRT/UFBoot` node labels |
| `results/04_phylo/<family>/iqtree.iqtree` | Best model, tree length, and ModelFinder table |
| `results/05_clusters/<family>.clusters.tsv` | Sequence-to-cluster assignment, with silhouette and representative |
| `results/05_clusters/<family>.cluster_summary.tsv` | Cluster-level statistics, monophyly, and support |
| `results/05_clusters/<family>.cutoff_scan.tsv` | Threshold sensitivity |
| `results/06_report/family_summary.tsv` | Family-level summary; in full-Pfam mode, unselected families are marked `not_run` |
| `results/06_report/report.md` | Overall report |

> In staged full-Pfam runs, families rejected by `03b` still appear in `family_summary.tsv` with `status=not_run`; they are not counted as successfully inferred trees.

**Reading branch support:** UFBoot >= 95 together with SH-aLRT >= 80 is usually considered strong evidence. If the two measures conflict or are both low, do not force a subfamily interpretation. UFBoot is not a Bayesian posterior probability and must never be reported as "PP = 100%".

**Biological interpretation of a cluster:** a cluster may be:

- a genuine orthogroup, suitable for cross-species comparison;
- a group containing paralogs, which cannot be used directly as a species tree;
- an artifact caused by long-branch attraction or alignment error. Check `mean_within`, `min_between`, and the tree.

## 8. Reproducibility

- All thresholds live in `config/config.sh` and are not scattered across commands.
- IQ-TREE uses a fixed `-seed 12345`.
- HMMER/MAFFT/trimAl/IQ-TREE versions are written to `results/06_report/software_versions.txt`.
- The coordinates, E-values, and source file of every domain are written to `metadata.tsv`.
- The pipeline is resumable; intermediate files are kept by default (`KEEP_INTERMEDIATE=1`).

> Note: MAFFT and IQ-TREE can produce tiny numerical differences across CPU counts or versions. Report the software versions, alignment mode, trimming mode, and random seed in the manuscript. For bit-wise reproducibility, fix the thread count.
